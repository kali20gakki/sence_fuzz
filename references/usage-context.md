# 使用场景与关键性画像

同一份代码，部署方式不同，测试重点就不同。一个离线 CLI 的崩溃是“重跑一次”；一个在线库的崩溃是“用户训练任务中断”。设计用例前先回答：**它被谁、以什么方式、在什么生命周期里使用，失败会炸多大。**

## 1. 画像模板

把答案写进 `<run>/01-context/usage-context.md`，至少包含以下字段：

| 字段 | 取值/说明 |
|---|---|
| artifact_type | library / SDK / service / CLI / plugin / daemon / kernel / script |
| integration | linked / preload / sidecar / proxy / framework-hook / standalone / embedded |
| caller | 谁调用；调用频率；调用线程；是否在热路径 |
| criticality | online（在线）/ offline（离线）/ batch；是否有 SLO |
| failure_blast_radius | process / host / cluster / data / user-visible only |
| lifecycle | one-shot / long-running / hot-reload / forkable / unloadable |
| concurrency | single-thread / multi-thread / async / reentrant / callback |
| perf_budget | latency、CPU、RSS、IO、线程、fd、日志量的预算或“不可退化”要求 |
| boundary_contract | 返回错误码 / 抛异常 / abort / undefined；谁负责校验 |
| compat_matrix | 版本、平台、ABI、多客户端、与其他组件共存 |
| observability | 日志、指标、错误码、trace；日志量/级别 |
| data_sensitivity | 是否接触用户数据/密钥；能否复制到 run 目录 |
| test_env | 真机/模拟器/容器；设备/端口/权限；是否可并行 |

## 2. artifact 类型 → 默认关注点

| 类型 | 第一优先级 | 必测维度 |
|---|---|---|
| 在线库 / SDK | 不打断宿主任务 | fail-safe、零 crash/abort、无死锁、开销有界、长稳、并发、边界、ABI、共存 |
| 离线 CLI / 工具 | 结果正确、可复现 | 参数/输入边界、错误处理、大文件、退出码、幂等、可重复 |
| 服务 / daemon | 可用性、延迟 | 启动/停止、配置、背压、限流、重启、优雅退出、多租户、资源泄漏 |
| 插件 / 注入组件 | 宿主兼容 | 注入失败、卸载、版本偏移、符号冲突、宿主 crash 隔离 |
| 内核/驱动 | 系统稳定 | 并发、资源、错误注入、卸载、兼容；必须额外评估权限与回滚 |
| 批处理 | 吞吐、正确性 | 大数据、分片、失败重试、断点、资源上限 |

## 3. 关键性 → 测试强度

- **online**：P0 必须覆盖“宿主任务成功 + 无 crash + 无挂起 + 开销/长稳 + 边界错误可返回”；功能性用例让位于稳定性。
- **offline**：P0 覆盖正确性、错误处理、输入边界、可复现；性能和长稳降为 P1。
- **batch**：P0 覆盖吞吐、失败重试、断点、资源上限；单次崩溃可接受但要可恢复。
- **安全/数据敏感**：额外覆盖越权、注入、路径穿越、日志泄漏；测试数据脱敏。

## 4. 不变量清单（可直接复用）

对在线库/注入组件，至少检查：

1. **I1 宿主任务成功**：输出正确、退出码符合预期、无未处理信号。
2. **I2 无 crash/abort**：SIGSEGV/SIGABRT/std::terminate/assert 都不允许。
3. **I3 无死锁/挂起**：超时内完成；回调/终止/并发场景不互相等待。
4. **I4 开销有界**：与关闭组件相比，wall/CPU/延迟不出现不可解释的劣化。
5. **I5 资源有界**：RSS、线程、fd、句柄、日志量在长稳中不持续增长。
6. **I6 数据正确/可对账**：采集/处理结果完整；丢数有计数、可解释。
7. **I7 边界错误可返回**：NULL/越界/非法枚举/权限/离线返回错误码或降级，不中断宿主。
8. **I8 可共存**：多实例/多进程/与其他 profiler/依赖版本共存不互相破坏。
9. **I9 长稳不退化**：长时间运行后吞吐/延迟/资源不持续恶化。
10. **I10 生命周期安全**：初始化、重复初始化、终止、终止后使用、重入、fork 安全。

## 5. 从画像推导用例

1. 为每个不变量写一句“可观测的 oracle”。例：I1 → “宿主计算的输出与关闭组件时逐元素一致，exit=0，无信号”。
2. 为每个 oracle 找“最可能破坏它的路径”：代码中的锁、回调、缓冲区、状态机、错误分支、资源释放。
3. 为每条路径设计“最小触发”与“加压触发”两个版本。
4. 给每个用例标 `criticality`/`invariant`/`blast_radius`，据此定 P0/P1/P2。
5. 如果某个不变量无法观测，先补观测（计数、日志、hook），不要用“看起来没问题”代替。

## 6. 画像评审清单

- [ ] 是否说明了“谁在什么进程/线程/生命周期里调用”？
- [ ] 是否说明了失败时用户会看到什么（崩溃/卡死/数据错/只是慢）？
- [ ] 是否把“不能打断宿主任务”转成了可执行 oracle？
- [ ] 是否有性能/资源预算，或明确“只要求不退化”？
- [ ] 是否识别了边界契约（错误码 vs 异常 vs abort）？
- [ ] 是否识别了共存/版本/ABI 约束？
- [ ] 是否识别了测试环境限制（设备/端口/权限/能否并行）？
- [ ] 是否把画像映射到了具体用例，而不是停留在描述？
