# 场景设计维度与 Fuzz 演进

用例不是“把 API 都调一遍”，而是用最少的 case 证明/证伪最关键的不变量。先按维度发散，再按风险收敛到 P0/P1。

## 1. 契约与边界

设计提示：

- 必填/可选、NULL/空、0、负数、SIZE_MAX、UINT32_MAX、INT_MAX。
- 枚举合法值/相邻值/越界值/`FORCE_INT`。
- 缓冲区：刚好、少 1 字节、多 1 字节、未对齐、只读内存。
- 字符串：空、超长、无终止符、非 UTF-8、包含路径分隔符。
- 版本：0、当前、当前+1、未来版本、旧 ABI。
- 重复调用：enable×2、disable×2、register×2、free×2、finalize×2。
- 顺序：先 disable 再 enable、先 stop 再 start、先 free 再 use。
- 输出参数：NULL、只读、短缓冲、未初始化。

Oracle：返回码/异常/errno 与文档一致；输出参数只在成功时被写；不 crash；不越界。

## 2. 状态机与生命周期

- 初始状态调用每个 API。
- 合法迁移全覆盖；非法迁移返回拒绝码。
- 终止中/终止后调用；并发终止；重复初始化。
- 资源释放顺序：先释放依赖再释放持有者；回调中释放。
- 重入：回调里调用同一 API；信号处理里调用；fork 后调用。

Oracle：状态与资源一致；无 use-after-free/双重释放；非法迁移可恢复；终止幂等。

## 3. 数据正确性

- 计数：产生 N 条，消费 N 条；丢数有计数。
- 顺序：时间戳单调/区间合法；跨流不乱序。
- 关联：request id / correlation id / trace id 能对上。
- 完整性：记录字段非空、长度合法、枚举合法。
- 对账：生产量 = 消费量 + 丢弃量 + 仍在缓冲量。

Oracle：可对账；不允许“看起来差不多”；差异要能解释。

## 4. 并发

- 多线程同时调用同一 API；不同 API 组合。
- 生产者/消费者速率不匹配；慢消费者；突发流量。
- 回调重入；回调中阻塞；回调中调用库 API（若文档禁止，单独验证不会死锁/崩溃）。
- 多进程/多实例；共享设备/端口/文件。
- 启动/停止与业务并发。

Oracle：无数据竞争（TSan 或计数对账）；无死锁；无丢失/重复；错误可返回。

## 5. 资源

- 长稳 RSS/线程/fd/句柄/临时文件增长。
- 缓冲区耗尽、队列满、背压、丢弃策略。
- 句柄泄漏、锁未释放、线程未 join。
- 日志量/磁盘占用；异常路径是否刷日志。

Oracle：资源回到基线或有界；丢弃有计数；无泄漏；日志量可控。

## 6. 故障注入

- 依赖缺失（库/配置/环境变量）、版本不匹配。
- 权限不足、设备离线、网络超时、磁盘满。
- 慢消费者、错误回调、返回错误/异常。
- 信号（SIGTERM/SIGINT）、进程退出、fork。
- 部分失败/重试/幂等。

Oracle：宿主任务仍完成（在线库）或失败可诊断（离线工具）；错误可返回；无 crash/挂起；可降级。

## 7. 负载与长稳

- 参数 ramp：N × 2、×10；并发 1→2→4→8。
- 短时峰值 vs 长时间稳定；周期 flush/GC/重连。
- 吞吐、P50/P95/P99 延迟、CPU、RSS、线程、fd、日志量。
- 与关闭组件/上一版本对比；记录方差与是否独占。

Oracle：无不可解释的劣化；无持续增长；吞吐/延迟在预算内；拐点可复现。

## 8. 稳定性 / fail-safe（在线库重点）

- 宿主任务输出与关闭组件时一致；exit code 正常；无信号。
- 库的错误路径不 abort/throw/terminate；不改变宿主全局状态。
- buffer 回调/终止/并发场景不互相等待。
- 初始化失败可降级；重复初始化/终止安全。
- 日志/回调异常不影响宿主。

Oracle：宿主任务成功是第一优先级；库错误可观测；不允许“功能正确但进程挂了”。

## 9. 兼容 / ABI

- 头文件与库版本组合；C/C++ 编译器；32/64 位；大小端（如适用）。
- 导出符号集合、结构体大小、枚举值。
- 多客户端/多实例/与其他组件共存。
- 旧数据/旧配置/旧 API 的兼容。

Oracle：符号/ABI 一致；跨版本行为符合文档；共存不互相破坏。

## 10. 文档 / 用户场景偏差

- 文档承诺 vs 实际返回码/默认值/限制。
- 样例能跑但边界不覆盖；文档示例与当前 API 不一致。
- 用户常见误用：NULL、忘记 finalize、重复订阅、在回调里调用。
- 安装/配置/权限与文档不一致。

Oracle：差异逐条列出；能运行验证的差异升级为 case；不能验证的标“文档风险”。

## 11. 从固定用例到 Fuzz

1. **参数变异**：合法值附近取边界/随机；记录 seed。
2. **序列变异**：随机 API 序列/状态迁移；每 seed 独立进程，防崩溃污染。
3. **并发 ramp**：线程/请求/负载逐步加，找拐点。
4. **故障组合**：依赖缺失 + 慢消费者 + 并发终止。
5. **差分**：开/关组件、旧/新版本、参考实现 vs 当前实现。
6. **最小化**：崩溃/丢数/挂起后，缩到最小参数/序列，再入库。

Fuzz 的 oracle 不是“没崩就行”，至少包含：返回码合法、宿主任务成功、资源有界、可对账、无超时。

## 12. 用例质量检查

- [ ] 有明确 hypothesis，而不是“测一下”。
- [ ] 有可执行 oracle（计数/返回码/输出/资源/时间）。
- [ ] 能映射到使用场景或不变量。
- [ ] 有最小触发与加压版本。
- [ ] 资源/超时/清理明确；可重复。
- [ ] 失败时能定位到证据，不需要重新猜。
- [ ] 不与已有用例重复；历史用例标了 reuse/evolve。
- [ ] 不是“为了数量”的低价值用例。
