# 报告标准

报告的第一读者是“要决定是否上线/是否修复的人”。结论先行、证据可点、局限诚实。**不要写没有证据的断言。**

## 1. 固定章节

1. **结论摘要**：findings 表 + 一句话总体判断 + 是否建议上线/继续加压。
2. **范围与方法**：目标、commit、构建、环境、工具、KG、并行策略、未覆盖范围。
3. **使用场景画像**：artifact 类型、集成方式、关键性、失败爆炸半径、生命周期、并发、性能预算、边界契约、不变量。
4. **被测系统理解**：架构、关键路径、状态机、文档契约、用户场景、历史用例。
5. **环境与基线**：CANN/driver/NPU/OS/编译器；源码快照 hash、库 sha256；baseline 结果；环境阻塞项。
6. **场景矩阵与覆盖**：case 表（ID/优先级/风险/lineage/资源/状态/证据）。
7. **稳定性、性能与长稳**：宿主任务连续性、开销、RSS/线程/fd/日志、soak 曲线、方差。
8. **高危问题分析**：每个风险主题的原因、代码定位、用例、观测、结论、残余风险。
9. **负结果与未触发风险**：测了什么、怎么测、为什么通过；还有哪些没测。
10. **局限与未覆盖**：环境/时间/工具/权限/样本限制。
11. **复现指南**：一条命令 + 依赖 + 资源 + 预期输出。
12. **并行执行与干扰分析**：jobs、资源、并发组合、串行复跑对比。
13. **后续加压/回归建议**：下一轮 seed、阈值、监控项。

## 2. 结论摘要表

| ID | 严重度 | 状态 | 结论 | 证据 | 影响 |
|---|---|---|---|---|---|
| F-001 | S1 | confirmed | ... | `05-evidence/C-08/...` | ... |

没有 finding 时也要写：

- “未发现 confirmed 缺陷；P0 覆盖 X，残余风险 Y。”
- 不要用“基本没问题”“看起来稳定”这类无证据措辞。

## 3. 严重度

| 级别 | 定义 | 发布建议 |
|---|---|---|
| S0 | 宿主中断/数据损坏/安全/不可恢复 | 阻断 |
| S1 | 功能错误/丢数/长稳退化/开销不可接受 | 修复后发布 |
| S2 | 边界/契约/泄漏/兼容，有 workaround | 评估后发布 |
| S3 | 文档/健壮性/体验 | 可排期 |

## 4. 写作规则

- 每个结论引用 `case id` + `05-evidence/...` 路径；代码定位用 `path:line`。
- 区分“观测事实”与“根因假设”；假设标 `hypothesis`，置信度。
- 性能数字必须带：基线、样本数、方差、是否独占、测量方法。
- 失败必须带：环境、重复次数、是否复现、最小化结果。
- 负结论也要写：范围、方法、为什么仍可能有残余风险。
- 不粘贴大段日志；引用路径 + 关键行/字段。
- 不暴露密钥/token/用户数据。
- 中文报告，代码/路径/字段保持英文。

## 5. 覆盖统计

`07-report/coverage.csv` 建议列：

```text
case_id,priority,risk,lineage,status,attempts,evidence,invariants,duration_sec,parallel_with
```

统计口径：

- 执行覆盖率 = 有 attempt 的 case / 计划 case；按 P0/P1/P2 分开。
- 有效覆盖率 = PASS + PRODUCT_BUG + ENV_BLOCKED 中有明确证据的 case / 计划。
- 不要用“代码行覆盖率”替代场景覆盖；没有覆盖率工具就明说。

## 6. 性能/长稳表

`07-report/perf.csv`：

```text
case_id,mode,iterations,threads,wall_sec,cpu_sec,p50_ms,p95_ms,p99_ms,rss_kb,threads_peak,overhead_pct,exclusive
```

`07-report/soak.csv`：

```text
case_id,elapsed_sec,rss_kb,threads,fd_count,throughput,errors,dropped,notes
```

要求：

- 至少 off/on 两组；或“无基线”说明原因。
- 长稳曲线按固定间隔采样；不要只给首尾。
- 并行数据单独标 `parallel_with`，不混入性能结论。

## 7. 高危分析模板

每个主题：

```markdown
### H1 <主题>

- **风险**：什么情况下会炸，爆炸半径。
- **代码定位**：`path:line`，关键锁/缓冲/状态机/错误分支。
- **用例**：C-xx、C-yy。
- **观测**：计数/时间/资源/退出码；并行/串行对照。
- **结论**：confirmed / not reproduced / residual risk。
- **残余风险**：没覆盖的版本/负载/平台。
- **建议**：修复/监控/回归。
```

## 8. 复现指南

- 一条最小命令；如果必须多步，给脚本路径。
- 依赖：构建产物、环境变量、设备、权限、数据。
- 预期输出：成功/失败的判据。
- 资源：是否需要独占、预计时长。
- 不要写“按报告操作即可”；给可复制命令。

## 9. 报告自检

- [ ] 结论摘要与 findings 一致；没有无证据结论。
- [ ] 每个 P0 有状态和证据；未执行项写清原因。
- [ ] 使用场景画像与用例映射一致。
- [ ] 稳定性/性能/长稳有基线、方法、方差、独占说明。
- [ ] 并行执行有干扰分析；关键计数有串行复跑。
- [ ] 负结果和局限诚实。
- [ ] 无密钥/敏感数据。
- [ ] 复现命令可执行。
